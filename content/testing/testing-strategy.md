## What is a Testing Strategy?

A testing strategy is a deliberate choice of **what** to test, at **which level**, and with **which tools**, so you get the most confidence per minute of test runtime and per hour of maintenance.

## The Test Pyramid

| Level | Scope | Speed | Quantity | Catches |
|---|---|---|---|---|
| Unit | One class or function | ms | Many | Logic errors, edge cases |
| Integration | Component + real DB/cache/HTTP stub | seconds | Some | Wiring, SQL, serialization, config |
| Contract | API producer/consumer agreement | fast | Per interface | Breaking API changes |
| End-to-end | Whole system through the UI/API | slow | Few | User journeys, deployment issues |

## Test Doubles

- **Stub:** returns canned answers.
- **Fake:** a working lightweight implementation, such as an in-memory repository.
- **Mock:** verifies that interactions happened.

Prefer fakes and stubs for state-based assertions. Over-mocking couples tests to implementation details.

## Judging Tests Written by an Agent

Ask one question about each test: **would it fail if the feature were broken?** Common failures:

- **Tautologies.** Mock returns X, assert X.
- **Only the happy path.**
- **Assertions that are too weak**, such as `assertNotNull(result)`.
- **Tests edited to match buggy output** ("updated snapshot").
- **Sleeping for async work**, which makes tests flaky.

A quick **mutation check** is to flip a condition in the code and confirm that a test fails. Tools like PIT (Java) and mutmut (Python) automate this.

## Common Mistakes

- Chasing 100% coverage with low-value tests while critical paths lack failure tests.
- E2E-heavy suites (an "ice-cream cone") that are slow and flaky.
- Shared mutable test data causing order-dependent failures.
- Not testing migrations, configuration or security rules because they "aren't code".

## Debugging Flaky Tests

Look for time dependence (inject a `Clock`), randomness (seed it), shared state, async timing (use Awaitility or polling with a timeout) and resource leaks. Quarantine flaky tests only with an owner and a deadline.
